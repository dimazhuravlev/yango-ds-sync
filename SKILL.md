# yango-ds-sync: макеты на актуальной ДС, ничего не сломав

Исполнитель — ИИ-агент (Claude Code или Codex) с подключённым Figma MCP; пользователь — любой дизайнер команды. Цель: макеты на актуальных компонентах,
стилях и переменных; вёрстка не поехала, данные не слетели, ничего содержательного не удалено; от пользователя —
минимум ручной работы.

Продукты: Yango (Yango Play), Allplay и суперапп Яндекс Плюс (ЯПС) — у них общая ДС. Бренд определяется по каждому
экрану и задаёт режимы `Product` / `Typography`, стили заголовков и варианты компонентов (`App`, `product`, акцент кнопок).
У Allplay шрифты как у Yango Play и своих вариантов в компонентах нет — правила в `references/text-and-color.md` →
«Бренд и режимы».

Только **мобильные** экраны. ТВ и Веб не трогать (у них свои ДС).

Папка скилла — каталог, где лежит этот SKILL.md (Claude Code: `~/.claude/skills/yango-ds-sync`, Codex:
`~/.agents/skills/yango-ds-sync`); все пути ниже — от неё.

Перед первым `use_figma`: загрузить скилл `figma-use`, если он есть у агента; прочитать `references/gates.md` (шлагбаумы и шаблоны просьб),
`references/sources.md` (что актуально), `references/rules.md` (правила ДС), `references/figma-api-gotchas.md` (грабли API). Для заглушек — `references/placeholders.md`.

## Что умеет

- **Перепись файла** (`03-census.js`): неактуальные компоненты по ключу (старая Платформа, ❌, форки, удалённые мастера),
  устаревшие приватные части Library на экранах, отвязанные копии, локальные мастера; тексты без стиля и на чужих
  стилях; чужие переменные; иконки с неверным размером.
- **Замена двойниками** (`references/twins.md`). Двойник — актуальный компонент Library, Графики или Органайзера того же
  назначения, что и легаси-, ❌- или чужой компонент в макете. Системные элементы, кнопки по цвету, таббары, навигация,
  чипсы, ячейки, шапки, карусели и карточки, шторки, тосты, виджеты, иконки. Подписи, картинки, видимость и геометрия
  переносятся, при расхождении замена откатывается сама.
- **Отвязанные копии** → инстансы Library (именной повтор или по ролям; карусели — целиком).
- **Тексты и цвета**: 28 стилей Library с учётом бренда экрана, режимы бренда, чужие переменные → `Theme`, сырые цвета →
  переменные при точном совпадении (всегда).
- **Слои** (всегда): пустые обёртки сняты, `bottom bar` собран, мусорные имена — по роли и по-английски; геометрия
  сверяется, при сдвиге вызов откатывается.
- **Страницы**: экраны 375 × 812, каркас Органайзера.
- **Шлагбаумы**: до правок сам проверяет права, подключение четырёх библиотек ДС, шрифты, слепок и не слетели ли подписи; версию и обновления
  библиотек просит по шаблонам в нужный момент (`references/gates.md`).
- **Сохранность**: слепок «до» в самом файле, сверка с ним, возврат слетевших подписей и картинок, подписи по обложкам,
  пересборка экранов-скриншотов на компонентах.
- **Масштаб**: большие файлы — параллельно субагентами по страницам по готовым брифам.
- **ДС**: перенос компонентов между файлами, перепись использования перед удалением, порядок публикаций, цвета в
  мастерах Library (`references/component-lifecycle.md`).

## Шлагбаумы: пользователь не знает процесса — проверяет исполнитель

От пользователя три действия, в таком порядке: сохранить версию файла; прислать ссылку и **не** принимать обновления
библиотек; принять обновления, когда исполнитель попросит (после слепка «до»). Исполнитель не полагается на то, что это
сделано: проверяет каждый шаг (`00a-preflight.js`, `00c`) и просит только недостающее — одним сообщением, по шаблонам
`references/gates.md`. Пока шлагбаум не пройден, файл не меняется. Версию в истории API не видит — её подтверждает
человек словом «сохранил». Мобильные страницы, бренд экранов и что вне задачи (ТВ, Веб, обложка) исполнитель определяет
сам; спрашивает, только если неоднозначно. В конце — вопросы пакетом и то, что MCP не умеет (публикация).

Окружение пользователя: Figma MCP с правом редактирования файла; шрифты бренда доступны в Figma: Yango Play и Allplay —
Yango Text и Yango Group Headline, ЯПС — YS Text и YS Display. Недоступные загружаются как личные (Settings → Your
uploaded fonts) — иначе тексты на них MCP не трогает; `00a` проверяет это сам.

## Процесс

Порядок жёсткий: каждый шаг защищает следующий. Скрипты собирать из папки скилла: `cd <папка скилла> && python3 scripts/build.py <скрипт> [NAME=значение]`
(подставляет ключи из `keys/`, ловит U+2028 и синтаксис) и вставлять в `use_figma` целиком. Одна страница — один вызов;
тяжёлые записи пачками; после обрыва соединения сначала перечитать состояние. Большие файлы — субагентами по
страницам (`references/agent-brief-*.md`), рецепты и сверка — у ведущего; если агент не умеет запускать помощников
(Codex), страницы идут по очереди теми же брифами.

0. **Шлагбаумы и слепок** (`gates.md`, Ш1–Ш6). `00a-preflight.js`: права, Library, шрифты, есть ли слепок, не слетели ли
   подписи раньше (по каждой мобильной странице); `get_libraries`: к файлу подключены все четыре ДС (`sources.md`). Подтверждение «сохранил» про версию. Allowlist свежий (`sources.md`).
   Затем `00c-snapshot.js` по каждой странице: слепок «до» в `sharedPluginData` и список ожидающих обновлений. Слепок —
   до любых правок и до принятия обновлений; уже снятый слепок не перезаписывается.
1. **Обновления библиотек** (Ш7–Ш8). Список пуст — шаг пропустить. Иначе попросить «Update all»; после «готово» — `00c`
   с `SNAP = false`, пока список не опустеет. Затем `01b-compare-with-snapshot.js` 'report', потом 'restore' (подписи и
   картинки, пока живы). Невозвратимое — копия сохранённой версии → `01-compare-with-copy.js` + `02-restore-texts.js`.
   Не возвращать то, что изменилось по дизайну Library.
2. **Перепись** `03-census.js` (+ опись Library `keys/library-components.txt` для сопоставления по имени). Учитывать
   только внешний неактуальный инстанс — вложенные уйдут вместе с ним.
3. **План и вопросы.** Каждой группе — двойник и рецепт из `twins.md`. Без двойника, со сменой смысла экрана, с
   ручными правками, которые сбросятся, — в вопросы пользователю пакетом, до замены (`rules.md` → «Как спрашивать»).
4. **Замены** по `twins.md`: сначала 1–2 штуки и скриншоты до/после, потом остальные. Проверка в том же вызове:
   подписи, картинки и геометрия родителей (защита `/*@GUARD*/` есть в каждом скрипте со вставкой). Скрипт возвращает
   `sample` — первый новый узел каждого типа: его экран снять до записи и после, без этого шаг не закрыт.
   После — `recipes/icon-size-audit.js`, таббары — `fix-tabbar-overrides.js`.
4b. **Заглушки → настоящие тексты** — только с разрешения дизайнера и только видимые на экране: ниже сгиба, под
   шторкой, мини-плеером или оверлеем, за краем экрана или контейнера — не вписывать, смысла нет. «Title», «Description»,
   «Artist», «Year» и подобные в карточках, независимо от того, слетели они или стояли в макете с самого начала (новые инстансы
   Library тоже бывают с текстом мастера). Спросить один раз на файл, шаблоном `placeholders-found` (`gates.md`), вместе
   с остальными вопросами шага 3; нет ответа «да» — заглушки не трогать, перечислить в отчёте. При «да» —
   `recipes/restore-titles-by-cover.js` по каждой мобильной странице: 'scan' (заглушки, обложки и смысл слотов с
   примерами из файла) → 'sheet' и один скриншот обложек → опознать → 'write' → 'clean'. Что вписывать в каждый слот —
   по примерам и `references/placeholders.md`. 'write' проверяет вёрстку карточки после каждого текста и откатывает
   то, что её сдвинуло (`fit`: подобрать короче); `sample` — снять до и после. Годы и авторы по памяти — пометить в
   отчёте; неопознанная обложка и заглушка без картинки — не выдумывать, в отчёт со ссылками.
5. **Формат и каркас** (если нужен единый вид страниц): `09-normalize-screen.js`, затем `08-layout-page.js`
   (`references/layout.md`).
6. **Режимы бренда, затем стили**: `recipes/set-brand-modes.js` (если нет фрейма страницы из 08) → `06-text-styles.js`
   (`BRAND`, `ONLY` пачками). Правила — `references/text-and-color.md`.
7. **Переменные и цвета** — всегда: `07-variables.js` (чужие коллекции), затем `07b-colors-to-variables.js` (сырой цвет
   с точной переменной → переменная). DRY, потом пачками по 6–8 экранов (`ONLY`). Хвосты мастеров Library — в отчёт.
8. **Гигиена слоёв** — всегда, после замен и стилей: `recipes/unwrap-wrappers.js` (навигационные и пустые обёртки) →
   `recipes/bottom-bar.js` (мини-плеер + таббар) → `10-layer-cleanup.js` (обёртки и имена по роли). Каждый — DRY, просмотр
   карты переименований, потом запись. Скриншот 1–2 экранов с `bottom bar` до и после.
9. **Сверка** (`references/verification.md`): перепись, `01b` 'report' со слепком, скриншоты, аудит иконок.
10. **Отчёт** пользователю (шаблон ниже).

## Правила, которые нельзя нарушать

- **Ничего содержательного не удалять** (слои с данными, компоненты); скрытое остаётся скрытым. Старый узел удаляется
  только после сверки текстов и картинок нового.
- **Классификация по ключу**, не по имени; id узлов между сессиями не хранить — только ключи.
- **Подписи, картинки, видимость, размеры снимать до свапа**; переносить по роли или имени, не по индексу слоя.
- **Замена не меняет родителя.** Новый узел вставляется через защиту `geoGuard`: сжатый hug-родитель возвращается к
  прежнему размеру, любой другой сдвиг родителя, соседей или самого узла — откат замены. Текст в дереве ещё не значит,
  что он виден: проверять обрезку (`01b` → `CLIPPED`, `FRAME`) и скриншоты.
- **`resetOverrides()` только с возвратом геометрии** и только при разной структуре; не на вложенных слотах.
- **Внутри мастеров Library и компонентов не из актуальной ДС — не чинить** в проекте: это хвосты ДС, в отчёт.
- **Пары состояний** («выбрано / не выбрано») **не автозаменять**.
- **В 🌈 Стили и в Library из проекта ничего не добавлять.**
- **Возвращать только то, что слетело** во время работы скилла (по слепку). Заглушки («Title», «Description»…),
  в том числе стоявшие изначально, заменять настоящими текстами только с разрешения дизайнера (шаг 4b). Прочие
  тексты, которые скрипты не меняли, не трогать; спорное — показать и спросить. Неопознанное (обложка, автор) не
  выдумывать.
- Пользователь может править файл параллельно: перед записью узел перечитать.

## Когда останавливаться и спрашивать

Непройденный шлагбаум (`gates.md`); нет двойника; удалённый мастер; замена меняет смысл или вид экрана сверх ожидаемого
(`verification.md`); инстанс несёт ручные правки, которые сброс уничтожит; расхождение со слепком, которого скрипты не
делали.

## Как пополнять скилл

Скилл общий: только то, что поможет на следующем файле, без имён, дат и отчётов по проектам (ход конкретного проекта —
в отчёте пользователю). Новый двойник → `references/twins.md`; новое правило ДС → `references/rules.md`; новая грабля
API → `references/figma-api-gotchas.md` в свою тему; проверенный скрипт → `scripts/` с `CONFIG` наверху; новые
компоненты ДС → `keys/` (`sources.md` → «Как обновить»). Новый скрипт со вставкой или снятием обёрток — только с
`/*@GUARD*/` и `GG.moved(N)` перед удалением старого узла. Скрипты — длинные строки: комментарий `//` ставить только в
конце строки или отдельной строкой, иначе он молча съест код после себя. Устаревшее — удалять, а не копить.

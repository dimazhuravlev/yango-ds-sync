# Бриф субагенту: заменить отвязанные и чужие элементы на компоненты 🫟 Mobile · Library

Ты — исполнитель одной группы замен в Figma-файле. Ведущий уже сделал перепись и выдал тебе список узлов
(id) и компонент-двойник из Library. Твоя задача — заменить каждый узел на инстанс Library **без потери содержимого**,
проверить и отчитаться. Работать только со своими узлами; соседние экраны и другие страницы не трогать.

## Инструменты

- `use_figma` (MCP `mcp__…__use_figma`; параметры `fileKey`, `code`, `skillNames: ['figma-use']`, `description`).
  Перед первым вызовом загрузи скилл `figma:figma-use`, если он доступен. Скриншоты — `get_screenshot` того же MCP
  (`fileKey`, `nodeId`, `maxDimension`): ссылку скачать `curl -sL -o /tmp/x.png "<url>"`, смотреть инструментом Read.
- Опись Library: `<папка скилла>/keys/library-components.txt` (имя | полный ключ | вариантов |
  страница). Оси вариантов — по месту: `importComponentSetByKeyAsync(key)` → `componentPropertyDefinitions`
  (у одиночного компонента — `importComponentByKeyAsync`). Готовые рецепты в `scripts/recipes/` и
  `scripts/pipeline/04b-replace-detached.js`, `04c-replace-detached-group.js` — читать блок «роли» и адаптировать.
- Грабли API (обязательно): страницу грузить `await page.loadAsync()` (текущую не переключать); `figma.notify` не
  работает; результат только через `return`, ≤ 20 КБ; `console.log` не виден; каждый вызов — отдельный контекст
  (id передавать строками); **узлы сравнивать по `id`, не по `===`** (`children.findIndex(c => c.id === x.id)`,
  не `indexOf`); тексты менять только после `loadFontAsync` всех шрифтов отрезка; ошибка внутри вызова откатывает
  весь вызов — писать по 1–5 узлов за вызов, проверку результата делать отдельным read-only вызовом.

## Правила качества (нарушение = брак)

1. **Содержимое 1:1.** До замены снять с узла: видимые тексты (с учётом скрытых предков), хеши картинок (`fills`
   типа IMAGE), видимость слоёв, свойства вложенных инстансов, размер и позицию (absoluteBoundingBox). После —
   сравнить. Расхождение → новый инстанс удалить, старый оставить, записать в отчёт. Старый узел удаляется только
   при полном совпадении.
2. **Геометрия как была.** Тот же родитель и индекс (z-order), та же ширина; в auto-layout — те же
   `layoutSizingHorizontal/Vertical` и `layoutPositioning`; вне auto-layout — те же x/y и констрейнты. Высота — по
   компоненту Library, если старая была «кривой» (нестандартной), иначе как была; разницу высоты записать в отчёт.
3. **Бренд экрана** (ведущий называет его в задании). У инстансов Library выставлять продуктовые оси: `Tabbar` → `App`
   бренда; `Top Navigation` → `App` бренда, `Platform=mobile` для экранов < 400; бейджи/нейплейты → `product` бренда;
   акцентные кнопки → `Type=accent <бренд>`. Тексты — стили Library этого бренда. Allplay: шрифты и стили как у Yango
   Play, своих вариантов у компонентов нет — какие брать, говорит ведущий; не сказал — не заменять, в отчёт.
4. **Размер иконки = вариант иконки.** У каждой иконки Графики (`icon / *`) внутри нового инстанса вариант `Size`
   обязан совпадать с фактической шириной фрейма иконки (20 → `Size=20`). При свапе глифа в слот — выбирать вариант
   нужного размера; после замены проверить все иконки внутри (`Math.round(width) === parseInt(Size)`).
5. **Без лишних слоёв.** Инстанс Library не заворачивать во фрейм, который ничего не делает (нет заливки/обводки/
   эффектов/паддингов, тот же размер). Если старый узел был такой обёрткой — результат кладётся напрямую в родителя.
   Верхнюю и нижнюю навигацию не объединять в один слой: `Header`/`Top Navigation` — отдельный ребёнок экрана;
   нижний блок — один вертикальный auto-layout фрейм `bottom bar` (mini-player сверху, `Tabbar` снизу, отступ 8,
   паддинги 0, без заливки, дети FILL по ширине, прижат к низу: STRETCH/MAX, в auto-layout-экране — ABSOLUTE).
   У `Tabbar` вложенный `underlay gradient` → `with player = true`, если мини-плеер есть и видим, иначе `false`.
6. **Карусели — целиком.** Отвязанная карусель (шапка + ряд карточек) заменяется одним инстансом `carousel / *`,
   а не шапкой и карточками по отдельности. Слоты карточек 01…06 — свап на мастер старой карточки + повтор
   оверрайдов по именному пути; лишние слоты скрываются булевыми свойствами.
7. **Не трогать:** киты других продуктов без двойника; компоненты и файлы, которые ведущий перечислил как «не
   трогать»; локальные мастера без двойника; скрытые слои остаются скрытыми; оформление страницы (Органайзер:
   `hStack`, заголовки, подписи). Ничего не публиковать, Library не редактировать.
8. **Родитель не меняется.** Вставка нового узла — через `geoGuard` (`/*@GUARD*/` в скрипте): до вставки
   `const GG = geoGuard(X)`, перед удалением старого `GG.moved(N)` пусто; иначе новый удалить, `GG.repair()`, в отчёт.
9. **Сначала один.** Каждый новый тип замены — на одном узле, скриншот до/после (`get_screenshot` старого и нового
   рядом), потом остальные пачками. Рендер сразу после правки бывает устаревшим — переснять.

## Порядок

1. Read-only дамп старого узла (дети до 3 уровней: имя, тип, размер, видимость, тексты, mainComponent) и
   компонента Library (вариант, дети, свойства). Сопоставить роли: какой текст/картинка/иконка куда едет.
2. Замена одного узла по п. 1–6, проверка read-only, скриншоты.
3. Остальные узлы пачками по 3–5, после каждой пачки — read-only сверка счётчиков (сколько старых осталось).
4. Финальный скриншот одного-двух экранов целиком (`maxDimension` 1200).

## Отчёт (кратко, по-русски)

Сделано: тип → сколько заменено / сколько осталось и почему (id). Проверено: тексты, картинки, размеры, иконки.
Что требует решения — со ссылками `https://www.figma.com/design/<fileKey>/?node-id=<id через дефис>`.
Без портянок и без пересказа механики.

# Figma Plugin API через MCP: грабли

Каждый пункт стоил минимум одного неверного прохода. Читать перед первым `use_figma`.

## Загрузка, обход, поиск

- `figma.skipInvisibleInstanceChildren = true` в MCP прячет **все** дети инстансов, а не только скрытые: поиск текстов
  находит только свои слои (434 вместо 5231 на одной странице). Ставить `false` и фильтровать видимость самим.
- `getNodeByIdAsync('<id страницы>')` для незагруженной страницы — null. Надёжно: `figma.root.children.find(p => p.id
  === id)` + `await p.loadAsync()`. `setCurrentPageAsync` — не больше одного раза за скрипт; узлы загруженных страниц
  читаются и пишутся без переключения.
- `figma.skipInvisibleInstanceChildren` в MCP по умолчанию `true`: скрытые слои внутри инстансов не видны. Ставить
  `false` в начале каждого скрипта.
- `findAll` / `findAllWithCriteria` на странице заходят в инстансы, только когда их поддеревья уже загружены. Поэтому
  «внешние» инстансы отбирать по признаку «нет предка-инстанса», а не по способу поиска. `findAll` на компоненте с
  чужой страницы может не зайти во вложенные инстансы — ручная рекурсия по `children`.
- Глубокий id `I<экз>;…` иногда возвращает null из `getNodeByIdAsync` — искать обходом: `screen.findOne(x => x.id ===
  id)`.
- **Узлы сравнивать только по `id`.** Каждый доступ даёт новый прокси: `===`, `indexOf` и `a !== root` при подъёме по
  `parent` молча врут. Индекс — `children.findIndex(c => c.id === x.id)`, подъём — до `a.id === root.id` или `PAGE`.
- После `swapComponent`, `detachInstance`, смены варианта ранее собранные потомки мертвы (`node … does not exist`):
  сначала собрать id внешних целей, потом обрабатывать по одному через `getNodeByIdAsync`; при `removed` —
  перечитать дерево.
- `componentProperties`, `variantProperties`, `componentPropertyDefinitions` у сломанных сетов бросают «Component set
  has existing errors» — всегда в `try`. `componentPropertyDefinitions` читать только у сета или одиночного компонента.
- У SECTION нет `opacity`, у GROUP — части свойств; `cornerRadius` бывает `figma.mixed` (брать `topLeftRadius`).
  Группа без детей и сет без вариантов удаляются сами — проверять `removed` перед `remove()`.
- Переименование «по имени» через `page.findAll` заходит внутрь инстансов и плодит оверрайды имён — отбрасывать узлы
  с предком-инстансом.
- В файле-потребителе у remote-сета `parent === null` — норма. Призрак (мастер удалён) определяется импортом:
  `importComponentSetByKeyAsync(key)` даёт not found, а `getMainComponentAsync()` при этом работает.

## Ответ, лимиты, откат, обрывы

- Результат только через `return`; `console.log` не виден; `figma.notify`, `saveVersionHistoryAsync`, `clientStorage`
  не поддерживаются.
- Ответ больше 20 КБ — ошибка без применения («Return value exceeds… not committed») или «Failed to parse SSE».
  Возвращать счётчики и до ~60 строк, группировать по экрану/хешу; не-ASCII экранировать; строки резать
  `Array.from(s).slice()` (эмодзи); U+2028 в коде и в ответе ломает разбор — в коде `String.fromCharCode(0x2028)`.
- Ошибка на верхнем уровне откатывает весь вызов — удобно для проверки «всё или ничего» (`throw` в конце). Ошибка,
  пойманная `try/catch` внутри цикла, не откатывает уже сделанное в итерации — убирать созданное в `catch`.
- Обрыв (`connection lost`, `ERR_NETWORK_*`) может прийти после применения: сначала read-only проверка, потом повтор.
- Тяжёлые вызовы рвут соединение: одна страница на вызов; фильтр по имени слоя до `getMainComponentAsync`; тексты для
  стилей брать из конкретных экранов пачками по ~10 (`ONLY` в 06), а не со всей страницы. Цвета (07b) — пачками по 6–8
  экранов, корни брать по id (`getNodeByIdAsync`), а не обходом страницы; обрыв бывает и на чтении — повторить половинами.
- Проверка геометрии по всей странице: хранить ссылки на узлы в снимке, а не искать каждый заново по id.

## Шрифты

- MCP не видит шрифты macOS и Adobe Fonts — только загруженные в аккаунт Figma: главный экран Figma со списком файлов (не внутри проекта) → аватар в левом верхнем углу → Settings → Account → Your uploaded fonts → Upload fonts → выбрать файлы шрифта (.ttf или .otf) → подтвердить права. Проверять
  `listAvailableFontsAsync` по семейству и начертанию — набор бывает неполным (только Bold/Medium). Semibold в стилях
  ДС Платформа — файл Bold: нет «Yango Text Bold» — не работают все стили …/Semibold.
- Шрифт, недоступный MCP: `characters` не меняется, `setProperties` с текстом падает, `resetOverrides` и
  `swapComponent` безвозвратно теряют оверрайд шрифта, скриншоты недостоверны. Такие тексты не трогать, просить
  руками. `setTextStyleIdAsync` требует только шрифт стиля — привязка к стилю работает.
- Перед `appendChild` / `insertChild` в auto-layout загрузить шрифты **всех** текстов переносимого поддерева и нового
  инстанса (иначе «unloaded font YS Text Bold»). Порядок: `setCurrentPageAsync(цель)` → `loadAsync` шаблонов →
  `clone` → вставка. На экране с режимом `Product` другого бренда шрифт меняется после вставки — грузить повторно.
- `setExplicitVariableModeForCollection` тоже требует загруженных шрифтов поддерева (недоступные можно пропустить).
- Грузить шрифты поддерева терпимо: скрытые тексты внутри инстансов бывают на недоступных шрифтах (SF Pro, Graphik
  Kinopoisk, Yango Text XBold). Падение `loadFontAsync` на одном шрифте не должно отменять перенос — `try/catch` на
  каждый шрифт; перенос после этого проходит.
- SF Pro Text / Display часто недоступны — время статус-бара не поменять (и не нужно).

## Свапы и свойства

- `swapComponent` на вариант, где локальный фрейм заменён инстансом с теми же именами слоёв, переносит все правки
  (тексты, видимость, подмены иконок, картинки, перекраску внутри иконок, отступы и размер корня). Так меняют
  структуру варианта без потери данных в макетах: новый вариант рядом + свап, а не правка старого на месте.
- `clone()` варианта кладёт копию на страницу, а не в набор — `set.appendChild(clone)`.
- На опубликованный вариант можно свапать без «Update all» в макете: `importComponentByKeyAsync(ключ)` даёт свежую
  версию; остальные компоненты файла не обновляются.
- Компоненты форка ДС хранят ключи вариантов оригинала: перепись по ключу находит их вложенные копии внутри чужих
  компонентов — массовый свап только по внешним инстансам (нет предка-инстанса).
- `swapComponent` переносит оверрайды только по совпадающим именам слоёв. Двойник с другими именами (сняли `❌`) —
  повтор состояния по именному пути (04). Свап на другой сет сбрасывает вложенные тексты и булевы — снять до,
  вернуть после.
- Имя слоя инстанса следует за именем компонента, пока его не переименовали. После свапа: своё имя вернуть, автоимя
  (имя старого сета, с `❌`) — заменить именем нового, иначе `❌` пришпилится к новому компоненту.
- Глиф иконки после свапа иногда падает в дефолтный (`love`): снять имя и вариант глифа до, вернуть
  `slot.swapComponent(<тот же вариант>)`. `setProperties` с INSTANCE_SWAP сохраняет размер инстанса-глифа и не
  перекрашивает вектор — после смены иконки перенести тинт (часто приходит сырой чёрный в `fills` или `strokes`):
  взять paint подписи хоста с переменной.
- Вариант выбирать по именам свойств (`setProperties`), не подстрокой имени варианта (`Large` совпадёт с `XLarge`).
  Вложенный инстанс с переопределённым руками вариантом за базовым не идёт — свапать напрямую. Глубокий INSTANCE_SWAP
  через `setProperties` родителя может не перерисоваться — свап на самом слоте.
- Текстовое свойство ≠ видимый текст: после свапа на версию, где текст привязан к свойству, на экран выходит значение
  свойства — ставить свойству записанные `characters`. Текст, равный тексту мастера, — не оверрайд: смена плейсхолдера
  в мастере его утащит.
- Свап инстанса, вложенного на два уровня, может отсоединить внешний инстанс — проверять тип носителя до и после.
- Свап на слоте-плейсхолдере может оставить новый инстанс скрытым — включать явно.
- Новый инстанс приходит с булевыми мастера, а не старого пресета (кнопки `Controls=true` у `Top Navigation`) —
  выставлять явно и сверять скриншотом.
- Смена `Platform` у `Top Navigation` может сбросить подписи табов на плейсхолдер — снять до, вернуть после. Смена
  варианта через `setProperties({Type})` теряет оверрайд ширины у FIXED-инстанса — вернуть `resize` + `HUG`.
- Оверрайд кегля переменной переживает свап атома — `resetOverrides()` на этом вложенном инстансе, затем вернуть
  `State` и подпись.
- Малые варианты иконок Графики — булева операция над инстансом 48-варианта: внутренний инстанс «Size=48 при 16 px» —
  не ошибка; `setProperties` на нём даёт «change would create a cycle». Аудит размера — только по внешним иконкам
  (`icon-size-audit` пропускает иконки внутри иконок).

## resetOverrides и геометрия

- Значение, равное мастеру, оверрайд не снимает; полностью снимает только `resetOverrides()`, а он сбрасывает размер,
  позиционирование, тексты, видимость. Только с возвратом геометрии: x, y, w, h, `layoutPositioning`, констрейнты,
  `layoutSizing*`, `layoutAlign/Grow`, видимость, прозрачность, имя.
- `resetOverrides()` на вложенном слоте откатывает и сам свап — для вложенных: свап + роли без сброса.
- `overrides` показывает не всё (таббар рисует 6-й таб и высоту мастера) — `resetOverrides()` допустим, если среди
  перечисленных полей нет содержательных (тексты, видимость, свойства).
- Вернуть заливку мастера без полного сброса: `master.fillStyleId ? setFillStyleIdAsync(id) : (setFillStyleIdAsync(''),
  fills = master.fills)` — переносится и привязка к переменной.
- Корень двойника может иметь другой режим размера (hug ↔ fixed) — вернуть `primaryAxisSizingMode`.
- `layoutPositioning = 'ABSOLUTE'` сбрасывает позицию — запомнить x/y. `resize` у FILL-ребёнка не работает — сначала
  `FIXED`. `resize` меньше 0,001 игнорируется. `resize` прямоугольника внутри инстанса молча не применяется.
- Ребёнок FILL, вынутый из обёртки в родителя без auto-layout, сжимается; текст, вынутый в auto-layout, может прийти с
  `FILL` по высоте и схлопнуться — сверять `absoluteBoundingBox` до/после и чинить `resize` / `HUG`.
- В экране auto-layout со `SPACE_BETWEEN` вывод первого поточного ребёнка в ABSOLUTE схлопывает поток.
- `layoutAlign = 'MAX'` игнорируется — выравнивать `counterAxisAlignItems` родителя. Первый ребёнок поверх остальных —
  `itemReverseZIndex`. Скрытые дети auto-layout хранят старые x/y — видимость проверять до геометрии.
- Хаг не пересчитывается после уменьшения ребёнка: `FIXED → resize → HUG`. `maxWidth` мастера (toast 280) не обойти.
- Пришпиленные `width/height` на HUG-инстансе рендерятся клиентом (наезжающие чипсы), хотя API показывает хаг —
  пересоздать инстанс или `resetOverrides()` с возвратом подписи.
- Предохранитель для структурных правок (удаление обёрток, смена вложенности): снимок `absoluteBoundingBox` всех слоёв
  до → после → `throw` при любом сдвиге.
- Auto-layout фрейм «по содержимому», у которого все дети ABSOLUTE, держит свой размер. `insertChild` кладёт новый узел
  потоковым — фрейм сжимается под него (виджет книги 354 × 247 → 57 × 57), а после перевода узла в ABSOLUTE размер не
  возвращается. Всё внутри обрезается, тексты при этом «видимы». Лечение — `lib/geo-guard.js`: снимок рамок предков до
  вставки, `repair()` возвращает размер и позиции детей (у детей с констрейнтом MAX позиция при сжатии тоже уезжает).
- Снимая обёртку в auto-layout, мерить ребёнка после `W.remove()`: пустая обёртка ещё занимает место в потоке, замер до
  удаления показывает ложный сдвиг на её ширину.
- В вертикальном auto-layout нижний ребёнок рисуется поверх верхнего: в `bottom bar` градиент таббара накрывает
  мини-плеер, тот выглядит блёклым. Ставить `itemReverseZIndex = true`.

## Перенос состояния (повтор)

- Путь к слою — массив `[имя без ❌ + номер среди тёзок]`, не строка через «/» (в именах бывает « / ») и не индексы
  (у двойника другой порядок детей — данные лягут не туда).
- Повторять по всем слоям (тексты, видимость фреймов, IMAGE-заливки, свойства и свап вложенных того же сета), не только
  по инстансам; свойства самого корня — отдельно.
- Разная структура — перенос по ролям: булевы по имени, тексты и вложенные по `componentPropertyReferences`.
- Стопка заливок у картинки (заглушка + затемнение + постер): переносить верхний видимый IMAGE (последний в `fills`).
  VIDEO-заливки не ставятся — фильтровать, в отчёт.
- Картинка исчезает из файла через минуты после удаления последнего носителя и через API не возвращается: старый узел
  удалять только после проверки хешей.
- Тексты переносить вместе с `fills` (красный текст ошибки теряется).
- Одинаковые тексты на экране («Title» в двух карточках): сопоставлять сначала по id, потом по тексту, потом по
  месту — мультимножество по тексту путает узлы.
- Локальный мастер с инстансами: правка в мастере стирает правки в инстансах на изменённых слоях — снять состояние
  каждого инстанса, править мастер, повторить.
- `detachInstance()` вложенного инстанса в мастере создаёт новые id — оверрайды инстансов на этих слоях отвязываются;
  ссылки `visible` на булевы сохраняются.
- Приватные двойники `. /` не импортируются по ключу — брать `mainComponent` вложенного инстанса внутри импортированного
  публичного родителя.

## Импорт, публикация, обновления

- Ключ сета — только в `importComponentSetByKeyAsync`, ключ компонента — в `importComponentByKeyAsync`; не тот метод
  отвечает «not found». Работает для опубликованных публичных компонентов даже без подключённой библиотеки; не работает
  для приватных и удалённых.
- Статус публикации проверять в файле ДС: `getPublishStatusAsync()` → `CURRENT` / `CHANGED` / `UNPUBLISHED`. Сет с
  ошибкой (дубли имён вариантов) не публикует новые варианты.
- Форк библиотеки хранит ключи оригинала: перепись и проверка обновлений его не отличают — смотреть имя сета и оси.
- В файле бывает две версии сета (устаревшая локальная копия): сравнивать id сета инстанса с id свежего импорта.
  Импорт по ключу иногда перепривязывает инстансы к свежей версии сам, но полагаться на это нельзя.
- После «Update all» такие пары копий остаются (Fade, status-bar, cell / master): тот же ключ, столько же вариантов,
  разные id сета. Если 01b чист — это не ожидающие обновления, повторно просить «Update all» не нужно.
- Приватные части ДС Платформа, поставленные прямо на экран, при «принять обновления» не обновляются — освежать через
  публичного родителя (04 `via:`).
- Принятие обновлений сбрасывает оверрайды там, где у мастера изменилась структура: хвост id вложенных узлов
  меняется (`;236:91907;…` → `;7529:8010;…`), место и внешний экземпляр — нет (на этом построен 01b). Счётчики
  оверрайдов Figma переучитывает — сравнивать содержимое, не счётчики.
- Оверрайды держатся по полному пути узлов: удаление слоя или новая обёртка в мастере отвязывают их во всех инстансах.
- Призрак локального мастера (`remote=false`, мастер удалён): структуру не поменять; восстановить — `detachInstance`
  одного → `createComponentFromNode` → остальные `swapComponent` на него.

## Переменные и режимы

- `figma.variables.getVariableByIdAsync` (не `figma.getVariableByIdAsync` — тот всегда null).
- `importVariableByKeyAsync` — только для переменных опубликованных коллекций подключённых библиотек. Коллекции с
  точкой (`.Color constants`) скрыты от публикации — двойник брать из `Theme`. Переменные Стилей в
  потребителе могут не отдаваться через `teamLibrary` — ключи брать в файле ДС Платформа, значение —
  `variable.resolveForConsumer(узел)`.
- `setBoundVariableForPaint` возвращает новый paint и сбрасывает прозрачность — альфа берётся из переменной, ставить
  `opacity = 1` (или вернуть, если переменная непрозрачная). Прозрачную точку градиента к переменной не привязать.
- Все 16 стилей ДС Платформа берут семейство и начертание из `Product` (YaPS & Allplay | Yango Play EN | Yango Play AR). Без
  режима на предке стиль покажет режим по умолчанию — YaPS & Allplay, шрифт ЯПС; режимы бренда ставить **до** привязки
  стилей и на каждую страницу.
- Версии коллекции. После переделки коллекции в файле живут её старые версии: тот же ключ, другой id (хвост
  `/2126:1` против актуального `/2248:32`), свои имена режимов. Пока на старую версию что-то ссылается (копия стиля
  старой версии, инстанс старого мастера, явный режим удалённого режима), в переключателе видны её опции с (!).
  Явный режим хранится по **ключу** коллекции и id режима: id режимов между версиями сохраняются (Yango Play 2078:1 =
  Yango Play EN), и `explicitVariableModes` может отдавать id старой версии для узла, который уже на актуальном
  режиме — это не ошибка. Чинить нужно только режим, которого в актуальной версии нет (Allplay 2078:2). Порядок:
  снять, потом ставить — `clearExplicitVariableModeForCollection(старая)` снимает и актуальную (общий ключ).
  Актуальная версия — коллекция переменной, к которой привязан стиль ДС Платформа (`importStyleByKeyAsync` →
  `boundVariables.fontFamily`).
- Удалённая или пересозданная (новый ключ) переменная Стилей не переезжает при «Update all»: слой остаётся на старой
  версии коллекции, и её режимы видны в переключателе с (i) / (!). Перепривязать: `recipes/ds-refresh-variables.js`.
- `overrides` инстанса помнит переопределение, даже если вернуть значение мастера: снять переопределение одного
  свойства нельзя, только `resetOverrides()` подынстанса (сбрасывает всё в нём). Поэтому на слоях внутри инстансов
  ничего не перепривязывать «заодно» — только то, что уже переопределено.
- `getPublishStatusAsync()` на сете / компоненте: 'CHANGED' — есть неопубликованные правки, потребители видят старую копию.
- У стиля из библиотеки id включает версию: в файле может жить несколько копий одного ключа; старая копия держит
  привязки к старым коллекциям. `importStyleByKeyAsync(key)` отдаёт свежую — свой текст перевести на неё
  `setTextStyleIdAsync(fresh.id)`; внутри инстансов уходит с принятием обновлений.
- У TEXT `boundVariables.fontFamily` / `fontStyle` / `fontSize` / `lineHeight` — **массив** (по сегментам), не объект.
- `setBoundVariable('fontFamily', переменная Product)` требует загруженных шрифтов всех режимов в начертании текста, и
  Figma подбирает родственные семейства (YS Text + Regular → «YS Text Display Regular»). При ошибке начертание текста
  может уже смениться — грузить все доступные варианты брендовых семейств и при ошибке вернуть `fontName.style`.
- Режим секции может инвертировать цвета скопированных компонентов — режим ставить на сам сет/экран, не на обёртку.
- Дети булевой операции не рисуют свою заливку (малые иконки Графики — union над 48-вариантом): сырой чёрный внутри —
  не баг, 07b такие узлы пропускает. Инстансы Графики — тоже ДС: цвет как в мастере — хвост, не переопределение.

## Скриншоты и проверка

- Скриншот рендерит холст: обрезанное родителем — чёрная полоса; компонент без фона — на белом (полупрозрачная белая
  кнопка «невидима»); `BACKGROUND_BLUR` не рисуется; `node.screenshot()` инлайн рендерит на белом. Сразу после правок
  `get_screenshot` может отдать старый рендер — переснять.
- Данные первичны, скриншот — контроль. «Ничего не изменилось» — сравнение SVG одного узла до/после
  (`svgIdAttribute:false`, `svgOutlineText:false`, вырезать `data:image`, перенумеровать id).
- Текстовая сверка не ловит бейджи, иконки и лишние кнопки — смотреть скриншотами.
- Узкий фрейм страницы (918 px) проходит размерный фильтр экрана 300–1400 × ≥ 600. Экран — только фрейм без вложенных
  экранов в рядах `stack` (так считает 10), иначе уборка слоёв снимет ряды каркаса и переименует секции.
- Несколько обложек сразу опознать: временный фрейм-контакт-лист на холсте (прямоугольники с `imageHash` + подпись
  хеша), один скриншот, потом удалить фрейм.

## Слепки в файле

- Namespace `yango_ds_migration` в `sharedPluginData` — прежнее имя скилла, не менять: под ним лежат уже снятые слепки
  в файлах команды, с новым именем скрипты их не найдут.
- `sharedPluginData`: namespace — только буквы, цифры, `_` и `.`; до ~100 КБ на ключ — резать на куски по 90 000
  символов. Хранить массивами (не словарём по пути — тёзки затирают друг друга), с x/y.

## Сборка компонентов в ДС

- У всех вариантов сета одинаковый набор ключей свойств, иначе сет ломается и вызов откатывается.
- `variant.clone()` кладёт копию рядом с сетом — нужен `set.appendChild(clone)`; клон теряет
  `componentPropertyReferences` — переписать по пути индексов. Сет с `clipsContent` не растёт — `set.resize()`.
- Одноимённые слои внутри атома ломают перенос оверрайдов между вариантами — переименовать до добавления осей.
- `createComponentFromNode` — только вне компонентов: `clone()` → на страницу → `detachInstance()` → убрать скрытое →
  компонент; локальный сет из готовых фреймов — `combineAsVariants`.
- Префикс перед точкой делает приватный компонент публичным: метку ставить после `. / ` (`. / ❌ spinner`).
- Вложенный инстанс экспонируется `isExposedInstance = true`; на родителе — `exposedInstances`.
- После массовых операций проверять мастера на «переворот» (`rotation ≠ 0`, отрицательные коэффициенты
  `relativeTransform`); тёмный вариант — сначала проверить `opacity` самого варианта.

# Оформление страниц и формат экранов

Все макеты лежат внутри фреймов страницы с блоками-заголовками, всё на auto-layout; страницы одного файла выглядят
одинаково. Компоненты оформления — 🦄 Органайзер (`keys/organizer-sets.txt`). Тёмное оформление — только обвязка:
экраны UI не перекрашиваются, содержимое экранов не меняется.

| Блок | Компонент | Ключ | Как выглядит |
|---|---|---|---|
| Заголовок страницы | `design-system`, `type=header` | `48dc15885e3de930d86ef4ed4f7fde505d84f16f` | крошки «<Проект> / <Страница>» + заголовок, ширина FILL; заголовок — свойство `Text#…` вложенного `header`, крошка — отдельный текст `breadcrumbs / page` |
| Подзаголовок группы | тот же сет, `type=subheader`, `Gap=true` | — | «RTL», «Promo Block»… |
| Заголовок секции | `header`, `Type=h5` (на страницах самой Library — `h6`) | `0677f3d961bd58028982ce615b1c28367b98c28c` | свойство `Text#…` |
| Подпись экрана | `paragraph`, `Type=p3` (в Library — `p4`) | `38278503f49f54ffda3c12b3b32b559017fc2790` | 375 по ширине |

Фон холста всех страниц — `#0D0D0D` (`page.backgrounds`); секции — `Surface/Two` #141414, радиус 24; у фреймов
экранов скругления нет (`cornerRadius = 0`). Старое оформление (кит Ядра `design-system` `bad2697c`, `header`
`cc58a0a6`, `paragraph` `a385bbb5`, светлые копии) заменяется Органайзером.

## Каркас

```
<Страница> (F)        V, gap 8, hug × hug, без заливки, имя = имя страницы без эмодзи
├─ design-system      type=header, FILL
├─ hStack (F)         H, gap 8
│   └─ <Секция> (F)   V, gap 48, pad 60, #141414, hug × FILL, имя = текст заголовка
│       ├─ header     h5 (если у секции есть имя)
│       ├─ hStack     ряд paragraph-подписей (если есть), gap 48
│       └─ hStack     ряд экранов, gap 48 (vStack — если экраны колонкой); экраны оригиналами
├─ design-system      type=subheader «RTL» (или другая группа)
└─ hStack …           секции этой группы
```

- Группа RTL — только при большом RTL-наборе; один-два RTL-экрана — в той же секции рядом с LTR.
- Порядок экранов в ряду — по `x` старого расположения; ряды старого расположения — отдельные секции. Секции
  называть по содержимому (Mobile / Tablet / States / RTL / имя компонента); подписи и заголовки — тексты старого
  оформления дословно, без хвостовых пробелов.
- Блок заметок (`header` h1 + `paragraph`) — не секция: имя и gap не трогать.

## Скрипты

- `09-normalize-screen.js` — сначала экраны: ширина 375; высота 812, если экран ≤ 1000 (ленты остаются своей длины);
  дети по положению до ресайза: верх (статус, навбар, навигация, шапка) → MIN, низ (таббар, мини-плеер, home indicator,
  шторка, тост) → MAX, от края до края → STRETCH. Ответ — что смотреть глазами (дети шире 375, переполнение).
  Шторка `Type=Fullscreen` со своим статус-баром на весь экран — не ошибка. Растровый мок экран не нормализует.
- `08-layout-page.js` — потом каркас по `SPEC` (страница, имя, крошка, бренд, группы → секции → подписи, экраны).
  Режимы бренда ставятся на фрейм страницы. Фрейм кладётся левее существующего; опустевшие старые обёртки
  перечисляются в ответе — удалять после проверки (это оформление, не содержимое).
- Гигиена слоёв — шаг по умолчанию после замен и стилей, в таком порядке, каждый сначала DRY:
  1. `recipes/unwrap-wrappers.js` — полноэкранные обёртки навигации раскладываются, пустышка вокруг одного компонента
     снимается. Не трогает обёртку, если она обрезает скругление, задаёт режим, несёт прототип, или если это экран в
     ряду оформления.
  2. `recipes/bottom-bar.js` — мини-плеер и таббар в один вертикальный блок, отступ 8, прижат к низу, мини-плеер выше по
     слоям (`itemReverseZIndex`), у `underlay gradient` — `with player`.
  3. `pipeline/10-layer-cleanup.js` — оставшиеся пустые обёртки и имена по роли. Не трогает отвязанные копии с именем
     компонента ДС, приватные части `. / …` и имена-пути `a / b`: по ним работают рецепты замены. Осмысленное имя
     снятой обёртки переходит к ребёнку с мусорным именем. Любой сдвиг слоя > 0,6 px — откат всего вызова.
  Секции и экраны с кириллическими именами не переводятся автоматически: они в `cyrLeft`, перевод — через `TR`.

## Рецепт сборки вручную (если скрипт не подходит)

1. `setCurrentPageAsync(целевая)` → `loadAsync` страниц-шаблонов → `clone` → `appendChild` (в другом порядке вставка
   падает на шрифте). Одна целевая страница — один скрипт.
2. Экраны переносить оригиналами (`row.appendChild(screen)`), не клонами: клоны рвут прототипные связи и комментарии.
   Если вставка в auto-layout падает на шрифте — собрать контейнеры обычными фреймами, положить экран, потом включить
   `layoutMode`; или `figma.group([node])` → вставка → `ungroup`.
3. До сборки — слепок раскладки (id, родитель, x, y, w, h); после — размеры перенесённых экранов не изменились, на
   странице ровно один фрейм страницы, скриншот.

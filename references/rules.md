# Правила ДС: что считается правильным результатом

Это принятые правила, а не рекомендации. Если задача упирается в одно из них — применять без обсуждения.
Новая ситуация, которой здесь нет, — спросить пользователя картинкой (раздел «Как спрашивать»).

## Что актуально

- Актуальны для мобайла: 🫟 Mobile · Library, 🦄 Графика (иконки, картинки, логотипы), 🦄 Органайзер (оформление
  страниц), 🌈 Стили (переменные). Ключи и файлы — `sources.md`.
- 🦄 Платформа / ТВ и / Веб актуальны только для своих платформ: в мобильных макетах их не ставить и не заменять.
  ТВ- и веб-страницы проекта не трогать вообще.
- Всё остальное — легаси: 🦄❌ Платформа / Мобайл, ❌ MiniApp Mob, 🌈 Платформа / Мобильные, 🌈 SuperApp *, 🦄 Ядро /
  Иконки, PlusUI Core (кроме логотипов PlusUI), форки Library, киты других команд.
- **❌ в имени компонента — легаси**, даже если компонент лежит в Library. Заменять.
- Классификация только по ключу компонента, не по имени: тёзок много, Library бывает подключена дважды, форк хранит
  ключи оригинала (различать по имени сета и осям).

## Что делать с неактуальным

- Есть двойник в Library / Графике / Органайзере — заменить (карта — `twins.md`). Пропущенный двойник — брак: перед
  заменами сопоставить все призраки, мёртвые, отвязанные фреймы и локальные мастера с описью Library по
  нормализованному имени (без ❌, пробелов вокруг «/», регистра, хвостовых чисел).
- Отвязанная копия компонента, который есть в Library, — тоже на замену.
- Удалённый компонент без двойника — оставить как есть, в отчёт.
- Киты других продуктов без двойника (книжная читалка, карточка тайтла чужого сервиса, экраны авторизации) — не
  трогать; их тексты и цвета можно перевести на стили и переменные ДС переопределением.
- Сырой скриншот чужого UI — оставить референсом. Сырой скриншот своего UI — пересобрать на компонентах рядом
  (бриф `agent-brief-rebuild.md`), скриншот оставить.
- Внутри мастеров Library и внутри компонентов не из актуальной ДС в проекте не чинить: это хвосты ДС, они
  чинятся в самой ДС. Исключение — замена 1:1 без изменения вида (отвязать призрак, свапнуть на тот же глиф).
- В 🌈 Стили и в Library из проекта ничего не добавлять: нужные цвета и стили там уже есть.

## Кнопки

- Единственная кнопка — `button` из Library. Чужие кнопки переводятся **по цвету**, а не по имени типа: старые
  сеты были в светлой теме, актуальный — в тёмной (карта — `twins.md`).
- Пара состояний «выбрано / не выбрано» (две кнопки, различающиеся только типом: табы `All`, ответы «Да/Нет») —
  не автозаменять: схлопнется состояние. Табы-кнопки верхней навигации переводить в `secondary` как есть или в
  `chips-row` / `chips-rounded` с активным первым; своё состояние не изобретать.
- Цвет кнопки, которого нет ни в одном типе (например красный), — не подбирать похожий, спросить.
- Пришпиленные к кнопке чужие токены заливки (`Light/Button/*`, `Dark/Fill/*`, сырой цвет) снимать, возвращая
  заливку мастера.

## Навигация

- **Top Navigation** — единый сет с осями `App` × `Type` × `Platform` × `RTL`. `Platform` по ширине экрана: < 400 —
  `mobile`, иначе `tablet` (бывшие пресеты `Size=Normal` 440 → `tablet`). Подписи и активный таб — из варианта.
  Булево `Controls` (правые кнопки) ставить явно по старому виду: в мастере оно `true`.
- Навбар экрана второго уровня (назад + заголовок/поиск) — Library `navbar` со статус-баром внутри; `Top Navigation`
  `Type=Second level` — для профиля и настроек.
- **Таббар** — единый `Tabbar` с осью `App`. Подписи — стандартные из варианта (свои подписи легаси не переносить),
  на языке макета. Порядок табов Yango Play: Watch · Search · Music · My Yango. В макетах раздела Music у таббара
  Yango Play активен `Music`. Полоска 34 px без табов — это `home-indicator / ios`, а не таббар.
- Верхняя и нижняя навигация — отдельные дети экрана, не в одной обёртке. Нижний блок — вертикальный auto-layout
  `bottom bar`: mini-player над `Tabbar`, отступ 8, прижат к низу; у `underlay gradient` таббара `with player` =
  видимость мини-плеера; мини-плеер выше таббара по слоям.
- Подложки: `Fade` — затемнение под навигацией Yango Play / ЯПС, `underlay gradient` — под навигацией Music. Если
  контент прокручивается под шапку, а у новой шапки нет своего градиента, добавить `Fade` (рецепт в `twins.md`).

## Карточки, карусели, шторки

- Карусель — только компонентом целиком (`carousel / Movies`, `carousel / Music / *`), не «шапка + карточки». Для
  топ-10 есть `carousel / Movies` `Type=top 10` (только `Size=medium`).
- Бейджи включать булевыми свойствами компонента (`Show top-10`, `Rating`…), а не скрытием слоёв. Плашки-заглушки
  «New», «Soon», `Badge` поверх карточек — мусор, удалять.
- Шапки блоков и каруселей — Library `header`; если рядом стоит отдельная шапка, а внутренняя скрыта, — включить
  внутреннюю (`Header=true`) и перенести заголовок.
- `modal-sheet` → `Bottom Sheet` `iOS / Halfscreen`: размер листа прежний, содержимое — локальный мастер в слоте
  `modal-sheet / placeholder`, шторка прижата к низу экрана.
- Экраны ошибок — только Library `error`.
- Инстансы Library с осью `product` / `App` — значение бренда экрана (бейджи, нейплейты, таббар, навигация). Для Allplay
  своих значений нет — какие брать, спросить один раз на файл (`text-and-color.md` → «Бренд и режимы»).

## Тексты, шрифты, цвета

- Тексты — только на 28 стилях Library (`text-and-color.md`). Без стиля — баг; чужой стиль — ближайший Library.
- Начертания Regular и Bold исключены полностью (Library · Base / Typography): Yango Text / YS Text — только Medium
  (11, 13, 15) и Semibold (18, 24, кнопки, заголовок навбара). Regular на экране — баг даже внутри чужого кита.
- Шрифты другого бренда в макете быть не может: в ЯПС — только YS Text / Display (через стили Library и режимы
  бренда), в Yango Play и Allplay — Yango Text / Yango Group Headline. Исключения: логотипы, текст книги в читалке.
- Экспериментальные шрифты (Yango Headline ML 2 Black, Yango Group Headline Var Heavy, YS Market VF) не трогать.
- Любой цвет, для которого есть переменная с тем же значением (hex и альфа в тёмной теме), — через переменную.
  Цвет без переменной не трогать. Переменная чужой библиотеки на инстансе Library может быть намеренной раскраской —
  не чинить.
- Время и тексты статус-бара не важны: не чинить, в отчёт и вопросы не выносить.

## Экраны и страницы

- Экраны телефона 375 × 812, длинные ленты — своей длины; компоненты тянутся по ширине, прибитые элементы — у
  краёв. Экраны без auto-layout адаптировать под 375 так, чтобы ручной работы осталось минимум.
- Страницы оформляются единым каркасом Органайзера на auto-layout (`layout.md`): фон холста `#0D0D0D`, секции
  `#141414`, у фреймов экранов скругления нет. Содержимое экранов при оформлении не меняется, экраны переносятся
  оригиналами.
- Иконка Графики: вариант `Size` равен фактическому размеру фрейма иконки.
- Слои: фрейм, который ничего не делает (без заливки, обводки, эффектов, тот же размер) вокруг компонента, —
  удалять; мусорные имена — по роли, по-английски (`screen`, `stack`, `title`, `description`…); имена компонентов и
  всё внутри инстансов не трогать.
- Ничего не удалять из содержимого: ни слои с данными, ни компоненты; скрытое остаётся скрытым. Скрытые
  альтернативные состояния, которые дублируют видимое, — в вопросы.

## Как спрашивать

- Всегда коротко, по делу, без воды и без подробного разбора деталей; подробности — только если человек попросит.
- Через результат, не через механику: скриншот или ссылка «сейчас так — как должно быть?». Без имён переменных,
  процентов, слов «оверрайд», «режим коллекции». Механику выбирает исполнитель и сообщает как факт.
- Пакетом, один раз, до замены спорного. Ссылка на ноду: `https://www.figma.com/design/<fileKey>/?node-id=<id через
  дефис>`.

## Публикация и обновления

- API не умеет принимать обновления библиотек, публиковать и сохранять версии — это всегда просьба к пользователю.
  Просить только когда без этого нельзя, формулировать одной фразой («опубликуй Library и напиши „готово“»).
- Порядок публикаций: библиотека-источник → библиотеки-потребители → макеты.

# Доработка компонентов ДС Платформа — приёмы

## Объединить несколько наборов в один (2026-10-29, `list-item / media`)

Задача владельца: пять наборов `list-item/<тип>/movies` → один набор с вариантами, как `list-item / music`; плюс книги.
Результат: https://www.figma.com/design/b8maDlvYFFs2vagJxwxc4A/?node-id=8775-2275

- **Собирать из копий, не переносить варианты.** Перенос существующих вариантов в новый набор сохраняет ключи, но
  свойства-переключатели получают новые id — включённые в чистовиках переключатели (там их были сотни) сбросятся.
  Копии + замена в проектах (`swapComponent` + `setProperties` по имени, проверка и откат) сохраняют всё.
- Перед сборкой — перепись использования по ключам вариантов во всех чистовиках (сколько строк, какие переключатели
  включены не по умолчанию) — это объём и риск следующего шага.
- Скрипт: `variant.clone()` → на страницу → имя `Prop=…, Prop=…` (у каждого варианта все свойства; несуществующим
  сочетаниям — значение по умолчанию: `Content=movie`, `Skeleton=no`) → `figma.combineAsVariants` на место старых →
  оформление набора (обводка-пунктир, радиус) как у соседей → раскладка: ряды по типу, колонки RTL.
- Переключатели: до клонирования снять `componentPropertyReferences` слоёв, указывающие на свойства своего набора
  (путь по индексам), после объединения `addComponentProperty` с прежними именами и умолчаниями и привязать заново.
  Ссылки внутри вложенных инстансов не трогать. Одинаковый смысл — одно имя (`Divider` у suggest → `Divider Bottom`).
- Старые наборы — `❌ ` в имени и описание «используйте …», не удалять до перевода чистовиков и публикации.
- Замена в чистовиках: `swapComponent(новый вариант)` → переключатели по имени → проверка (тексты, размер) → откат.
  `swapComponent` переносит подписи не всегда (одинаковые имена `label` во вложенных — часть теряется: tv-channel,
  RTL-downloads). Новый набор — точные копии, поэтому до замены снять видимость и тексты всех слоёв по путям индексов,
  после — вернуть расхождения. Откат (`swapComponent(старый)`) подписи не теряет.
- Вложенная обложка, которую в проекте подменили (книга вместо постера), при смене структуры не переносится сама:
  снять `Type` / `Ratio` / `Progress`, картинку (fills с IMAGE) и текст прогресса — и выставить на новой карточке.
- Отличие в 1 px из-за округления пропорции (7:10: было 109, стало 108) — допуск только для книжных строк.
- Строки внутри мастеров ДС (`title`) — заменить в самой ДС, в проекты придут после публикации.
- Итог задачи 2026-10-29: ЯПС 131 строка (26 книжных), Watch 194 из 195 (одна — старая версия компонента, +4 px),
  ДС 36 в `title`. `modal-header` не использовался — удалён из набора (владелец); `regular` RTL=on пока не используется, оставлен для арабских экранов.

## Карточка, высота которой следует ширине (пропорция)

`card / book xsmall` в каруселях — фиксированная высота 114 и ширина по пропорции; в строке списка нужна ширина 76 и
высота по пропорции (аудиокнига 76×76). Отдельный размер (`Size=list`) не нужен:
- в мастере размер карточки задаёт прямоугольник `size`: `layoutSizingHorizontal = FILL` + `lockAspectRatio()`;
  сама карточка — ширина FIXED (как была), высота HUG. В каруселях ничего не меняется;
- в строке — слот 76 (FIXED, высота HUG), карточка в нём на всю ширину (FILL). Смена `Ratio` / `Type` у вложенной
  карточки сразу меняет высоту строки.
- Замок пропорций на самой карточке-инстансе не работает: он запоминает пропорцию в момент замка и не следует за сменой
  варианта. Замок — на внутреннем слое мастера каждого варианта.
- Плагин: замок на узле, у которого высота HUG, не тянет высоту; ставить на узел с FIXED по обеим осям, потом FILL.

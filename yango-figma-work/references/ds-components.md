# Доработка компонентов ДС Платформа — приёмы

## Объединить несколько наборов в один (2026-10-29, `list-item / media`)

Задача владельца: пять наборов `list-item/<тип>/movies` → один набор с вариантами, как `list-item / music`; плюс книги.
Результат: https://www.figma.com/design/b8maDlvYFFs2vagJxwxc4A/?node-id=8775-2275

- **Собирать из копий, не переносить варианты.** Перенос существующих вариантов в новый набор сохраняет ключи, но
  свойства-переключатели получают новые id — включённые в чистовиках переключатели (там их были сотни) сбросятся.
  Копии + замена в проектах (`swapComponent` + `setProperties` по имени, проверка и откат) сохраняют всё.
- Перед сборкой — перепись использования по ключам вариантов во всех чистовиках (сколько строк, какие переключатели
  включены не по умолчанию) — это объём и риск следующего шага.
- Скрипт: `variant.clone()` → на страницу → имя `Prop=…, Prop=…` (у каждого варианта все свойства; несуществующим
  сочетаниям — значение по умолчанию: `Content=movie`, `Skeleton=no`) → `figma.combineAsVariants` на место старых →
  оформление набора (обводка-пунктир, радиус) как у соседей → раскладка: ряды по типу, колонки RTL.
- Переключатели: до клонирования снять `componentPropertyReferences` слоёв, указывающие на свойства своего набора
  (путь по индексам), после объединения `addComponentProperty` с прежними именами и умолчаниями и привязать заново.
  Ссылки внутри вложенных инстансов не трогать. Одинаковый смысл — одно имя (`Divider` у suggest → `Divider Bottom`).
- Старые наборы — `❌ ` в имени и описание «используйте …», не удалять до перевода чистовиков и публикации.
- Замена в чистовиках: `swapComponent(новый вариант)` → переключатели по имени → проверка (тексты, размер) → откат.
  `swapComponent` переносит подписи не всегда (одинаковые имена `label` во вложенных — часть теряется: tv-channel,
  RTL-downloads). Новый набор — точные копии, поэтому до замены снять видимость и тексты всех слоёв по путям индексов,
  после — вернуть расхождения. Откат (`swapComponent(старый)`) подписи не теряет.
- Вложенная обложка, которую в проекте подменили (книга вместо постера), при смене структуры не переносится сама:
  снять `Type` / `Ratio` / `Progress`, картинку (fills с IMAGE) и текст прогресса — и выставить на новой карточке.
- Отличие в 1 px из-за округления пропорции (7:10: было 109, стало 108) — допуск только для книжных строк.
- Строки внутри мастеров ДС (`title`) — заменить в самой ДС, в проекты придут после публикации.
- Итог задачи 2026-10-29: ЯПС 131 строка (26 книжных), Watch 194 из 195 (одна — старая версия компонента, +4 px),
  ДС 36 в `title`. `modal-header` не использовался — удалён из набора (владелец); `regular` RTL=on пока не используется, оставлен для арабских экранов.

## Карточка: в карусели ведёт высота, в строке списка — ширина (пропорция)

`card / book xsmall`: в каруселях высота 114, ширина по пропорции; в строке списка ширина 76, высота по пропорции
(аудиокнига 76×76). Отдельный размер (`Size=list`) владелец не хочет — «тот же размер, отличается только ведущей стороной».
Проверено 2026-10-29:
- **Мастер ведёт высотой** (как карусели): карточка HUG/HUG, внутренний `size` FIXED (ширина по пропорции × 114) +
  `lockAspectRatio()` на `size`. Карусели: смена `Ratio` меняет ширину, высота 114.
- **В строке переопределение на инстансе**: карточка `layoutSizingHorizontal = FILL` в слоте 76 и внутренний `size`
  тоже `FILL` по ширине (вложенный размер переопределять можно). Тогда ведёт ширина, высота — по замку пропорции,
  и это переживает смену `Ratio` / `Type`. Делается в мастере строки — в проектах наследуется.
- **Нельзя**: делать мастер карточки «ведёт ширина» (FIXED ширина + FILL `size`) — в каруселях вложенные карточки после
  смены варианта сохраняют ширину (76) и вырастают по высоте (поймано 2026-10-29, карусель книг ЯПС сломалась);
  замок пропорции на самом инстансе (запоминает пропорцию момента замка); `resize` вложенного слоя в инстансе (не держится).
- После любой правки размеров карточки — проверить и карусели, и строки (инстансы в ДС и в чистовиках).
- Строки, где вложенную карточку уже переключали (`Ratio` / `Type` — переопределение) ДО появления в мастере строки
  `size = FILL`, этот FILL не получают: карточка 76 × 114, аудиокнига обрезана. Починка — в самой строке:
  `size.layoutSizingHorizontal = 'FILL'` на вложенной карточке; держится при дальнейших сменах пропорции. Новые строки
  из ДС работают сразу (проверено на свежем инстансе в ЯПС 2026-10-29).

## Вариант с локальной копией атома → инстанс атома (2026-10-29, action bar `mini-player`)

Задача владельца: в `State=player` пилюля плеера была локальным фреймом, а не инстансом атома `. / mini-player / player`
(в остальных состояниях — атом); вариант стоял в ~275 экранах ЯПС / Music / Watch с разными наборами контролов.
Результат: https://www.figma.com/design/b8maDlvYFFs2vagJxwxc4A/?node-id=8791-517

- **Не менять структуру варианта на месте.** Замена фрейма инстансом внутри мастера меняет id слоёв — в макетах после
  «Update all» слетят подписи, обложки, скрытые и подменённые иконки. Вместо этого:
  1. рядом — новый вариант: копия старого (`variant.clone()` кладёт копию на страницу — `set.appendChild`), локальный
     фрейм → инстанс атома с тем же именем слоя, FILL; тексты и картинка атома по умолчанию — как у старого варианта
     (иначе в макетах без своих подписей вылезет текст атома);
  2. старый — `… old` в значении свойства и описание «не использовать»; новый — первым в наборе и на месте старого
     (тогда он по умолчанию в ассетах), старый — отдельным рядом ниже;
  3. сверка нового со старым: слои по путям имён (позиция, размер, видимость, тексты, заливки) + попиксельно
     (скриншоты, `numpy`); владелец публикует;
  4. в макетах — `scripts/swap-variant-verified.js` по страницам: импорт нового варианта по ключу (принимать обновления
     не нужно), `swapComponent`, сверка каждого инстанса, всё или ничего; сначала 1–2 штуки и скриншоты до/после;
  5. перепись: старых 0 → старые варианты удалить из ДС, вторая публикация.
- `swapComponent` переносит правки по именам слоёв и через границу «фрейм → инстанс»: тексты, видимость, подмены
  иконок, картинки, перекраску внутри иконок, отступы и размер корня — проверено тестом до записи (временный набор
  в ДС, удалён в том же вызове).
- Отличия атома, допустимые по дизайну ДС: тексты FILL + обрезка вместо HUG — в сверке под `track name` не сравнивать
  ширину и x (в RTL текст прижат вправо, рамка шире); проверять, что видимый текст не обрезается.
- Компоненты форка ДС (чужая библиотека-черновик) хранят ключи вариантов ДС: вложенные в них плееры находятся по ключу
  старого варианта. Свап внутри чужого инстанса не делать — сам чужой компонент заменить двойником ДС (экземпляр
  нужного варианта на то же место и в тех же габаритах, подписи — с чужого, затем чужой удалить).
- Снимок инстанса, который на экране вне клипа (под шторкой, за краем), — картинка 1×1: для сверки брать другой.

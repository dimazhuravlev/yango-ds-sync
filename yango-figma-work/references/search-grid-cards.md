# Карточки в масонри-сетке поисковой выдачи (ЯПС «Общий Поиск», 2026-11-02)

Сетка: 3 колонки по 109, карточки растянуты на ширину колонки (FILL). Отвязанные карточки — заменить на ДС:

Карта владельца (2026-11-02). Заголовок — до 2 строк, подзаголовок — 1 строка; все подписи 13px Medium:

| Тип | Карточка ДС | Подзаголовок |
|---|---|---|
| трек | `card / album` `Size=small` + включить скрытую `button` (play) | исполнитель |
| альбом | `card / album` `Size=small` | исполнитель |
| плейлист | `card / playlist` `Size=small` (или `card / album` small — оба ок) | — |
| артист | `card / artist` `Type=cover, Size=small` | — |
| автор книги | `card / artist` `Size=small` | «автор» |
| фильм, сериал | `card / poster` `Size=small` (medium тоже ок) | год |
| режиссёр, актёр | `card / poster` | роль |
| аудиокнига | `card / album` `Size=small` | автор |
| книга | своей карточки нет — локальный фрейм: `card / book` + `card / text` снизу, зазор 6 | автор |

Постер растягивать **только на инстансе**: карточка FILL и вложенный `container` FILL, показать `text`, включить
`Description` у `text-label`; мастер ДС не трогать (фиксированная ширина в мастере ломает карусели — 18 постеров,
2026-11-02). Обложку брать с отвязанной (fills с IMAGE).
**`swapComponent` между размерами постера теряет картинку** (переопределение fills на `image` сбрасывается) — снять
fills до свапа и вернуть после, сверить хэш.

Правило владельца для всех карточек сетки — **локально, только на этих инстансах**: белый заголовок — не больше 2 строк,
серый подзаголовок (если есть) — 1 строка; `textTruncation = 'ENDING'`, `maxLines` 2 / 1 (переопределение в инстансе
работает). Подписи в мастерах ДС не правим.

Проверка замены: высота карточки и видимые тексты совпадают с отвязанной (с учётом скрытых предков); иначе откат и
картинка «было → стало» владельцу.

Сетка без подписей (плашки на месте карточек, текстов нет) — это **скелетон** того же экрана, не выдача: не заменять,
оставить плашками (`references/skeleton.md`). Проверка по текстам такие сетки откатывает сама — так и надо.

**Порядок записи при замене (грабля 2026-11-02, потеряно 5 карточек):** вставить новую → проверить → собрать строку
отчёта (имя, id старой) → только потом `old.remove()`. После `remove()` у старой не читать ничего (`name` бросает
«does not exist»), а `catch` удаляет новую карточку **только на этапе сборки** (флаг `stage = 'build' | 'commit'`).
Иначе исключение после удаления старой уносит и новую — в макете дыра, вернуть можно только из истории версий.
